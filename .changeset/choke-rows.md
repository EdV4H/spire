途中で必ず通るノードを作れるようにした（`chokeRows`）。

```jsonc
"skeleton": { "grid": { "cols": 5, "rows": 12 }, "walks": 6, "chokeRows": [5] }
```

指定した行のノードを1つに絞る。ウォークは必ず全行を通るので、**全ルートがその
ノードを通る**（テストは `paths()` で全経路を列挙して確認している）。
`{ "rule": "fixedRow", "row": 5, "type": "boss" }` と組み合わせれば中ボスになる。

行0と終端行は拒否する。`minStarts`/`maxStarts` と `maxEnds` が既に持っている
ので、1つのことに2つのつまみを与えない。

**バグ修正: `maxEnds` が守られていないことがあった。** 開始列がグリッド全体から
選ばれていたため、着地ブロックに届かない列から始まったウォークが自分の終端ノードを
作り、上限を超えていた（5列2行・開始4つ・`maxEnds: 1` で終端が最大4つ）。既存の
プロパティテストは `minStarts: 1, maxStarts: 1` に固定していてレーンが1本しか
無かったので、露見しませんでした。開始列は行0が許す窓から選ぶようにした。

内部的には、終端の絞り込みと choke 行を同じ「ゲート」として扱い、各行の窓を
その交差として求めている。交差しても窓は1行あたり1列しか動かないので、交差を
作らないという保証はそのまま成り立つ。
